# Remembered transfers — 0.3.1

iPhone shows up to eight unfinished download shortcuts with filenames and committed byte counts. Reconnect and resume uses a previously scanned/pinned pairing if it is still valid, checks the sender's current manifest, and continues only when file hash, total size and sender identity match. A different file is not accepted automatically. If previously displayed saved bytes cannot be restored, the shortcut stops and asks for an explicit new acceptance rather than silently downloading the whole file.

Pairing credentials are stored only in the app's device-local Keychain, not in the history JSON or a synced/cloud store. If Keychain saving fails, the filename/progress shortcut remains and scanning is available. Disconnect and clear pairing deletes remembered credentials for that peer while retaining file progress. Scan fresh code on an unfinished item authorizes a new session and resumes only if it matches the selected unfinished file. Filenames and file identities are kept privately in backup-excluded app storage. Completed/discarded entries are removed; checkpoints not listed in the bounded history can still be recovered by scanning the same file or cleared using Discard all incomplete downloads.

Android keeps up to three immutable private copies of selected outgoing files across Stop sharing and normal app restarts. Share last file again reopens the latest selection; Saved shared files selects another remembered file. It verifies the retained copy's hash before starting a fresh hotspot/server session. Forget saved shared files stops the session and removes the private copies, preserving original files and received files. Newer selections evict older copies after the metadata update commits. No server session is started automatically on app launch.

Leaving iPhone Nearby now explicitly pauses a resumable download and requests a short system-granted grace period to finish cancellation/cleanup. This does not enable continuous background transfers. Return and resume. Android home-screen behavior is not made into a background-service guarantee; its snapshots are retained even if its process is later destroyed. iPhone-to-Android uploads remain one-shot foreground transfers.

Wi-Fi joining remains manual for the user's free SideStore setup. Existing credentials can reconnect only while Android's session is still valid/reachable. If Android restarted sharing, use a fresh QR. Remembered files eliminate the document-picker step; they do not bypass Wi-Fi authorization, certificate pinning or expired-token checks.

The user's reported restart-from-zero case was ambiguous and has not been reproduced exactly. Regression tests cover clearing pairing without deleting progress, missing checkpoint data refusing an automatic restart, different-file rejection and a background-pause/reconnect transition through the production iPhone model.

Validation pending. Physical hotspot reconnection, actual home-screen/suspension behavior, retained copies across updates and Keychain behavior after SideStore signing still require a phone test. Uninstalling iPhone removes download progress; uninstalling Android removes its saved files and changes its sender certificate, preventing reuse of checkpoints bound to that old identity.
